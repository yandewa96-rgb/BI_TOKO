Alasan memilih StandardScaler (z-score) & log-transform

  1. Skala berbeda jauh: Monetary dalam ratusan ribu rupiah, Frequency 1–14. K-Means memakai jarak Euclidean, sehingga tanpa scaling Monetary akan mendominasi pembentukan klaster.
  2. Standardisasi (rata-rata 0, std 1) menyamakan bobot ketiga fitur dan tidak memaksa rentang tetap seperti Min-Max, sehingga lebih tahan terhadap nilai ekstrem.
  3. Log pada Monetary: distribusinya miring ke kanan (skewness {{ S.rfm.Monetary.skew()|num(2) }} → {{ S.X.Monetary_log.skew()|num(2) }}); log meredam pengaruh pelanggan bernilai sangat besar tanpa membuang mereka.

4f · Strategi untuk dataset berukuran besar

Soal 4f

1 · Agregasi

Ubah {{ sm.baris_akhir|num }} baris item menjadi {{ S.trans|length|num }} baris nota dan {{ S.rfm|length|num }} baris pelanggan sebelum modeling. Aplikasi ini sudah melakukannya — K-Means berjalan pada tabel pelanggan, Apriori pada matriks nota.

2 · Chunking

Jika berkas jutaan baris, baca bertahap (read_csv(chunksize=…)), akumulasikan agregat per pelanggan/nota/produk per potongan, lalu gabungkan; memori tetap konstan.

3 · Sampling

Untuk eksplorasi: ambil sampel acak per pelanggan (bukan per baris) agar RFM tidak rusak, atau MiniBatchKMeans. Untuk Apriori naikkan min. support dan batasi panjang itemset.
